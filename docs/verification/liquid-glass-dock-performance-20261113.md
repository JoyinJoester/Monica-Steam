# Monica Steam 液态玻璃 Dock 验证（2026-11-13）

用户授权对上一轮三文件优化进行构建、功能回归和前后性能对照。本轮没有继续修改生产逻辑。运动、高光和内阴影源码与验证开始时的冻结副本逐字节一致；具体 SHA256、安装包哈希、调用参数和结果见同名证据目录的 `results.json`。

## 已确认的结果

- 54 项相关 JVM 测试通过，无失败、错误或跳过。
- API32 共 15 个不同设备方法取得通过结果，包含原实现阴影对照与两种帧采集夹具；前序失败保留，不称首次整批全绿。
- 优化后的拖动位置在每个事件中立即发布，1000 次后不增加活跃子任务；新选择覆盖旧松手回调，销毁取消任务，减弱动画与越界拖动正常收敛。
- 阴影透明再显示恢复完全相同像素，颜色、偏移、尺寸及复用可变 Path 的形状变化正常刷新。
- 原生触摸下正常字号及 1.5 倍字号／减弱动画各 5 次点击、1 次拖动，合计精确 12 次选择回调。材质变化、切换设计风格保留草稿、旧页面销毁及减弱动画也通过。
- 已查看 API32 原实现与优化后的正常／大字号四张底栏联系图，标签和选中状态正常。截图使用合成棋盘背景，不代表完整 Steam 页面视觉验收。

## 拖动事件开销对照

同一 APK 编入原实现和优化后的运动状态。每组先预热 200 次，再处理 1001 次合成拖动事件；三组交替顺序执行。数据取自 `optimized-api32-native07`，单位为每组总量。

| 指标 | 原实现三组 | 优化后三组 |
| --- | --- | --- |
| UI 线程 CPU（ms） | 407.172 / 146.766 / 139.627 | 11.451 / 11.572 / 13.639 |
| ART 分配增量（bytes） | 6668784 / 6422528 / 6474008 | 1458176 / 1458176 / 1458176 |
| 首事件后／整组后子任务数 | 各 2 / 2 | 各 2 / 2 |

CPU 中位数约 146.8 → 11.6 ms，分配中位数约 6.47 → 1.46 MB，减少约 77.5%。原实现首组仍有 JIT／预热影响；分配统计覆盖整个进程。这个人工压力场景支持“事件调度开销下降”，不能换算成真实手势的帧率倍数，也没有证明原实现活跃子任务无限增长。

## 原生窗口帧对照

使用 ActivityScenario、实际 Activity.setContent、系统 Choreographer 与 Window.FrameMetrics；不依赖 Compose 测试规则的空闲判定。静态合成背景，回调仅更新本地页签，不加载 Steam 页面或联网。预热两次手势后执行 12 次交替拖动和 20 次交替点击。采用优化 → 原版 → 原版 → 优化顺序。

API32、x86_64、SwiftShader 软件 GPU，`runtimeShader=false`：

| 运行 | 拖动中位数 / P95（ms） | 点击中位数 / P95（ms） |
| --- | --- | --- |
| optimized07 | 20.336 / 21.744 | 10.663 / 20.258 |
| baseline08 | 20.821 / 23.381 | 20.621 / 22.414 |
| baseline09 | 20.817 / 25.937 | 20.702 / 27.953 |
| optimized10 | 20.369 / 22.116 | 11.595 / 23.190 |

每组拖动约 950–961 个、点击 445–624 个窗口帧样本，采集回调丢失数为 0。绘制阶段耗时也下降，但拖动总耗时中位数改善较小，点击尾部耗时有重叠。这里的 FrameMetrics 总耗时不等于显示帧间隔，不能用它计算实际 FPS；固定 16.67 ms 阈值仅作描述。软件 GPU、共享主机负载和合成页面限制了结果的外推。

## 构建与前序失败

1. 原 Debug 配置实际开启 R8 且不可调试。首轮 1468.157 s 完成主／测试包，但 54 项 JVM 中 1 项仍要求已删掉的无用途 `KERNEL_SU_PRESSED_SCALE` 常量。仅移除该过期源码断言；可见缩放、折射材质和拖动／松手约束保留。重新运行 216.392 s，54 项全过。守卫文件中设计风格入口的其他变化属于既有工作。
2. R8 包的首次 instrumentation 因 `androidx.tracing.Trace` 缺失崩溃，未执行任何方法。不能把它记成用户应用崩溃，也不能声称 R8 运行回归已通过。后续使用独立包名 `takagi.ru.monica.steamapp.dockperf`、未混淆且可调试的 x86_64 测试包；主／测试包联合构建 1203.201 s。
3. 阴影第一次像素对比在原实现和优化版都得到相同差值 6375303。实际图像显示首张捕获的是内容提交前的窗口背景。夹具改为等待空闲、250 ms 和硬件 frame commit；完全相同像素断言未放宽，两版随后通过。
4. 本地额外 Kotlin 夹具首次用 `.java.srcDir` 配置，未被 Kotlin 编译。改为 `.kotlin.srcDir` 后补建并核对测试数量；那次旧构建不计为原实现夹具验证。
5. 原实现的旧 Compose 空闲夹具 3 项中 2 项超时；优化版该夹具通过。无法据此认定用户应用崩溃或卡顿主因。失败运行残留的 `frames.json` 是旧优化版结果，已排除；有效性能对照使用上述原生时钟夹具，采集前清理本任务输出。

## 高版本环境结果

API35／16K AVD 在当前 Emulator 37.1.11 下，前 8 项运动及两版阴影检查通过后，测试进程在 ART JIT 线程的 `ClassLinker::ResolveMethod` 出现 SIGSEGV。启动期间桌面、输入法等也有 ART JIT 原生崩溃。该批没有完成，也没有产生可验收的折射帧数据；原始日志保留。

已有 API36.1／4K AVD 在 `swiftshader_indirect`、`swiftshader` 和原配置 `host` 模式均出现 SurfaceFlinger／ranchu mapper 的 `!rcEnc->featureInfo()->hasReadColorBufferDma` 断言；软件模式测试被系统崩溃中止，host 模式在测试启动前就出现。首次目录清理权限失败未执行测试；脚本随后只对本次独立测试包执行清理，避免陈旧结果。没有改生产代码、测试断言、ART 设置或 AVD 配置来规避故障。

使用已有 Emulator 35.2.10 复用相同 API35 AVD，启动阶段仍记录到 system_server 在已编译的 `ComponentResolver`／`IntentResolver` 方法中的原生空指针崩溃。没有安装或继续跑对照夹具，也没有把旧引擎这次启动计为通过。因此本轮高版本折射／色散实际帧表现未取得有效对照；API32 的回退材质结果不能代替该项验收。

为移除 API36.1 独立测试包，另做一次仅清理用途的启动，使用本次进程的 `-feature -GLDMA`／`-feature -GLDMA2` 覆盖，未更改配置文件。日志确认覆盖生效，但系统仍触发原断言，package 服务未就绪，卸载命令被拒绝。该启动没有进行性能测试。
