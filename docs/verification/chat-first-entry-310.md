# Steam 1.0.310 首次进入聊天验证

2026-11-20。用户指出第一次从 Dock 打开聊天卡顿，随后切换顺畅。本轮只改初始化与本地会话标记读取，保留已有页面复用、玻璃过滤条和语音行为。

## 原因与修改

冷进程采样在主线程发现多份 SecurityManager 构造：聊天缓存、群缓存、发件箱和会话偏好。资料库进入聊天的采样中合计约106.88ms；同一次 trace 的时间不作为验收耗时。四个存储入口改为实际读写时再打开加密存储，原算法、密钥、格式和缓存身份校验不变。

置顶、归档、隐藏标记的整批读取移到 IO。结果容器绑定存储实例、账号、会话 ID 集合和偏好修订；新集合先处于待准备状态，列表不绘制未经筛选的行。取消读取不能把旧账号结果写入新容器。消息时间／连接变化不重复读取相同 ID 的本地偏好。

## 检查与失败记录

- 初始19 JVM检查通过；加密构造／往返、评测UI／公开API及页面生命周期等15设备检查通过（9.451s）。
- 优化主／测试包构建10m55s成功，46 JVM通过。优化包运行器在执行测试前因 androidx.tracing.Trace 被裁剪退出；不把这个批次算作设备通过，应用本身从正常入口可启动。
- 玻璃页面上设备自带uiautomator dump发生139退出，保留日志，真实Activity的页面状态改用截图核对；帧数据来自dumpsys gfxinfo，未使用该崩溃进程计数。
- 使用独立gamedetail包设置合成主密码和玻璃样式。仅该测试包临时允许截图；未修改用户应用的保护设置。手机Dock测量临时设420dpi/竖屏，随后恢复原物理280dpi/自由旋转。

## 最终回归与清理

为运行 AndroidX 测试，单独构建 non-debuggable、未压缩的 x86_64 测试变体，独立包名不变；没有增加生产 R8 保留规则。instrumentable01 主／测试包构建8m26s成功，device-final01 整批35/35通过，runner25.135s。包含加密存储延迟初始化／首次写入和重建读取、后台读取标记／准备期不闪现隐藏会话／旧账号迟到结果隔离、TabHost生命周期、列表与Dock动效、游戏双页、商店价格及评测恢复。

该批之后发现评测筛选失败分支的最后修改尚未进入旧编译产物，故补 instrumentable02 主／测试包及18项评测／路由JVM检查，2m26s成功；编译类确认不再捕获旧筛选状态。更新安装后，评测3项再次通过，runner3.938s。此项增量没有修改聊天代码；聊天7份生产源哈希仍与R8实际Activity测量版本完全一致。最终评测分支仅由未压缩包覆盖，不宣称已经过R8运行验证。

只卸载本任务的 gamedetail／gamedetail.test 两包及自有临时XML。原0/10/11/12、原应用、1080×1920、280dpi、字号1.0与自由旋转（accelerometer=1、rotation=0）保留或恢复，预先运行的MuMu继续运行。首次严格包列表相等检查因新增的 com.monicapass.kmp／takagi.ru.monica 两个无关包而失败；原基线包均仍存在，这两个新增包也予以保留，没有清理它们。
