# Monica Steam：聊天玻璃与页面过渡验证（2026-11-09）

本轮只修改 Monica Steam，保留任务开始前的未提交改动。版本仍为未发布 1.0.310；没有提交、推送、发布或交付 APK。

## 实现

- 聊天列表筛选栏和富媒体面板分类栏使用真实背景采样。列表在筛选栏下方滚动，静止时通过测量后的顶部留白保持原有布局；面板分类与关闭按钮采样自身内容区域。液态玻璃使用折射与高光，M3E 使用轻磨砂。未读、私聊、群聊等仍为互斥选择。
- 两处选中指示块共用 220ms 过渡，动画值在绘制阶段读取，避免每帧重新组合整份列表；减少动画设置下直接定位。
- 原生聊天玻璃按来源共享 RenderNode 录制，释放最后一个消费者时移除观察器。源内容变化、控件移动与更换来源均刷新；装饰性重绘复用录制。折射参数按尺寸和圆角缓存，边缘渐变缓存，渐进模糊从四层减为三层。
- Steam 顶层和子页面统一短距离滑入（宽度的 1/20、220ms）与淡入（160ms），返回反向，减少动画时仅 100ms 淡入。旧页面不保留退出动画，不对整页玻璃缩放。顶层底栏页面使用不同内容键，切换方向跟随配置顺序。商店和游戏库的既有 WebView 禁用过渡条件保留。

## 验证方法与边界

构建使用项目独立 Gradle 用户目录、单 worker；未停止其他项目的 Java 进程。测试使用独立应用 ID `takagi.ru.monica.steamapp.glassmotion` 和原生夹具 `com.monica.telegramchat.glassmotiontest`，仅合成数据，不登录真实 Steam 账号。

本地 M3E Canvas 草图在实现前建立并实际预览；草图、链接和原生截图仅保存在忽略的 `docs/design/glass-motion-20261109/`。原生截图检查包括液态玻璃聊天列表、筛选移动中间帧、1.5 倍字号富媒体底栏和背景切换对照。Canvas 仅用于布局审查，不作为玻璃渲染通过证据。

API 32 只能覆盖平台模糊回退；API 33 以上才支持运行时折射着色器。帧样本来自 Debug、x86_64、软件 GPU，不用于宣称真机 FPS、流畅度百分比或所有 OEM 问题均已解决。本轮未做 R8 性能测试。

## 已知失败及修正

旧原生代码的两项负向对照均失败：六个玻璃控件的来源绘制计数为 13，且控件移动后出现旧位置背景。共享录制修复后，同样受控更新为 2 次（一次正常遍历、一次共享录制），纯装饰重绘不再录制来源。

初次 Java 编译因 lambda 引用未初始化 final 字段失败，改为方法引用；首个应用构建因 init script 早期访问 rootProject 失败，修正为独立初始化配置。原始失败日志保留。

首批应用测试 15 项中 3 项失败：背景对照采到了不变的标签文字；减少动画断言早于 Compose 卸载帧；输入法尚未完成 startInput 就注入 composing span。后续 25 项批次中 24 项通过，唯一失败的指示条截图全部为白色，未当作真实页面。最终测试改为采样背景、等待实际硬件帧提交，并在输入法可见且 editor 激活后设置组合输入；保留原功能断言，未修改搜索生产代码。

现有 API 36.1 虚拟机在 `swiftshader_indirect` 与 `swiftshader` 两种启动参数下，均在应用安装前出现 SurfaceFlinger 的 `hasReadColorBufferDma` 断言崩溃。启动完成标志一度为 1，但 ActivityManager 随后不可用，首次原生测试命令未能启动。两份系统崩溃日志及失败命令保留，不计入应用测试。停止该实例后改用已有 API 35 虚拟机验证着色器；未改 API 36 的注册文件与 config.ini。

API 35 启动阶段也记录到一次 system_server 崩溃，之后系统恢复并完成测试。首批原生测试 11 项中 8 项通过，3 项玻璃像素断言失败；附加诊断确认所有失败采样读到 `ff1a1b20`，与截图中的系统 ActionBar 背景一致。API 35 边到边模式使夹具内容从 y=0 开始，旧 ActionBar 覆盖了位于 y=100 的玻璃控件。仅在裸渲染夹具隐藏平台 ActionBar，与生产 Compose 宿主一致；保留所有像素阈值和生产代码。最终原生 11 项全部通过（22.926s），包括 Kyant 折射、尺寸变化、切换材质、来源更新与释放。最初一次诊断重跑误用已安装旧测试包，明确保留为旧包失败，不当作新夹具验证。
