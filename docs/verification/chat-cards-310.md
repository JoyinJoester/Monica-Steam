# Steam chat cards — implementation and verification

Date: 2026-11-10. Scope: Monica Steam only, existing unreleased development version.

The user requested broad Steam card coverage and actions from chat. Source/design work was prepared while the main Monica Android task owned the shared resources. On 2026-11-10 the user explicitly released build/device use through that task; its source message was read and confirmed before verification resumed. Debug compilation, 81 JVM tests and 20 distinct API 32 device methods have passed. No real Steam message, trade, gift, invitation, or account operation was performed.

## Source-only follow-ups

After the verification described below, the user requested code-only changes and reserved build/device resources for the main project. The current tree therefore differs from the verified packages: the refresh indicator clears the filter row; Start trade moves from the share sheet to the private-chat header menu; game invitation cards use a compact body and overflow menu; and confirmed private-chat messages can be hidden locally after confirmation. The user explicitly accepted local-only private-chat deletion. See `chat-card-menu-310.md` for current behavior and static checks. None of the build/JVM/device results below covers these follow-ups. The historical source hashes and original test logs remain unchanged.

## Originally verified behavior

The existing chat layout and send/reply/outbox path are retained. The attachment panel now has “Steam cards & trading”. Direct chats can open the selected friend's Steam trade form; group chats have no invented trade recipient. The external form uses its own signed-in Steam account; the share sheet states this rather than implying that Monica credentials are transferred. Users can paste a supported link or choose their own profile, inventory or broadcast, inspect a local preview, and add it to the conversation-scoped draft. Only the existing Send control submits the composed message. The new preview performs no metadata lookup.

| Content | Received representation | Available action |
| --- | --- | --- |
| Trade link | `tradeofferlink`, legacy `tradeoffer` with a new-offer URL, plain/BBCode URL | Open the Steam trade form, copy link |
| Trade offer | Official `id`/`sender`, legacy ID aliases, numeric offer URL | Open the referenced offer; inconsistent URL/ID cannot open another offer |
| Inventory item | `econitem`, existing item aliases, inventory URL | Open inventory/asset or supplied Market listing; Steam economy image token |
| Workshop/community content | `publishedfile`, file-details URL | Open original content; title/description and supported Steam preview image |
| Screenshot/artwork, video/clip, guide, collection | Published-file type | Distinct card title and original-content action |
| Broadcast | `broadcast`, `broadcastinvite`, watch URL | Open broadcast; invitations can use the message envelope sender |
| Broadcast view request | Existing request tag | Readable card and original source; no fabricated approval action |
| Group/community/chat | `inviteurl`, existing invitation aliases, group/chat URLs | Open provided group/invitation or validated invite code |
| Profile/friend | Profile and friend-invite links; existing friend request aliases | Open supported destination |
| Game/lobby/Remote Play | Existing game/lobby tags and recognized Steam invitation URLs | Open invitation through a compatible installed app; copy invitation link; existing Store action retained |
| Store | Existing app card, bundle/package links | Existing app navigation; open bundle/package |
| News/event, comment, Market | Supported links and existing aliases | Open supported destination when supplied |
| Gift and unknown notifications | Existing gift aliases and unknown Steam tag fallback | Readable source, recognized gift link when present; no local redemption or fabricated system messages |

These are render/open/share capabilities, not full Steam desktop feature parity. Generic community URLs do not prove whether content is a screenshot, video or guide; only a supplied published-file type selects those subtypes. Direct group invitations without a usable invite code/URL, broadcast approval, gift redemption, voting, accepting trades, creating a game lobby, and acquiring an invitation token remain outside this implementation. Sharing an existing game invitation link does not create a new lobby. Published videos/clips open their source rather than adding another inline player. Existing stickers, emoticons, effects, attachments and game sharing are retained.

Cards use localized neutral labels rather than asserting that a gift, item or trade was verified. The original body remains available. Single-card captions are retained; multiple card blocks/URLs fall back to complete readable text. New profile/Workshop/Market shares remain discoverable in the history link category; typed published images/videos use media.

Card actions permit recognized destinations on exact Steam hosts and a narrow set of game invitation schemes. They reject userinfo, custom ports, path traversal, unrelated hostnames and privileged Steam commands. Unknown message types do not gain an action just because a URL is present. Preview images use an explicit Steam host/path allowlist. Failure to find an external handler shows a localized message and keeps the conversation open. This restriction applies to the new cards; ordinary text-link behavior is not a general URL security redesign.

## Evidence and limits

- Cached official Steam web-client dictionaries/renderers were inspected for `tradeofferlink`, `tradeoffer` (`id`, account-ID `sender`), `econitem`, `publishedfile`, `inviteurl`, `broadcast`, game/lobby invitations, and Playtest/broadcast requests. Excerpts are local under `.codex-tasks/20261110-chat-cards/raw/`. Legacy gift/comment/event aliases are compatibility behavior, not newly confirmed server notifications.
- Three editable local Canvas pages were inspected before implementation. Source JSON, local share URL and images remain in ignored `docs/design/chat-cards-20261110/`; project key `monica-steam-chat-cards-20261110`. Canvas is a flow/design artifact, distinct from the later native captures.
- Debug main and Android test packages compiled in `debug01` (212.684 seconds); its combined JVM step was 80/81 because an old assertion expected a now-supported Steam profile URL to remain plain text. The test now checks an ordinary external URL, while the new profile-card tests cover the changed behavior. `debug02` passed all 81 JVM tests in 25.839 seconds, with no failures, errors or skipped methods. The main APK did not change.
- `cards01` passed the initial 6 card UI methods (15.373 seconds runner). `debug03` added native theme/action coverage (29.309 seconds). The subsequent `cards02` run passed 16/20 methods (68.018 seconds runner); four theme methods stopped because the selector matched both the conversation's trade button and the sheet's trade button. The fixture now requires the sheet dialog ancestor, retaining the displayed-state assertion. `debug04` rebuilt only the test package (25.299 seconds). The same main APK then passed all 14 card methods in `cards03` (46.110 seconds runner). The 6 original `TelegramChatUiTest` methods passed in `cards02`; therefore all 20 distinct selected device methods have passing results, but the original 20-method batch was not all green.
- The 14 card methods cover disabled invalid links, group recipient limits, conversation-key isolation, 1.5 font scale reachability, original-message preservation, actual native Attach/Add/Send behavior, exact partner/offer intents, clipboard copy, independent game-invitation/store actions, and missing/denied handler containment. `ActivityMonitor` intercepts external ACTION_VIEW intents. No Steam activity or transaction was started. Missing-handler tests deliberately throw ActivityNotFoundException/SecurityException; they do not simulate an OEM package manager.
- Four native chat/theme combinations (M3E and Liquid Glass, light and dark) were exercised with the real chat thread, native composer, share sheet and backdrop host. Twelve normal-font Chinese captures (thread, sheet, draft) were inspected as a contact sheet, with original light-theme thread and dark glass sheet also inspected separately. Captures remain ignored locally. API 32 checks the platform blur/fallback path; it does not validate API 33+ AGSL lens rendering or GPU frame performance.
- All 48 new keys have nonempty values in English, Chinese, Japanese, Russian and Vietnamese: 240 localized values with XML, duplicate-name, key parity, reference and placeholder checks. Scoped grammar/whitespace checks pass across 16 Kotlin files. Translations were checked structurally, not reviewed by native speakers.
- Tests used the existing public `Monica_Issue136_API_32` x86_64 AVD and independent package `takagi.ru.monica.steamapp.chatcardstest`. Main/test manifests were checked to omit INTERNET. A new secondary user could not be created because the AVD already had its maximum five users; no existing user was removed and the user limit was not changed. Isolation used the previously absent package in the original owner user. Both test packages were removed, original users 0/10/11/12/14 and the original owner's package set were verified unchanged, and this task's emulator was stopped. Registration/config hashes remain unchanged; the original disks are retained. MuMu and other Java processes were not modified.
- Failure records remain in the evidence. The setup driver initially treated `pm path` exit 1 (package absent) as an error; corrected before installation. The first screenshot export used column-formatted `ls`; corrected to `ls -1` and re-exported separate PNGs. These tooling issues are not counted as successful tests.

The isolated minified release build passed in 236.391 seconds (`release01`), including R8, resource shrinking and Compose mapping. It used a local init-script package/ABI override and a debug signing key; production signing configuration was not changed. The release was not installed. All production card sources were unchanged between the initial Debug build and this Release build; only two test files changed during runtime verification.

Static evidence is in `chat-cards-310-static.json`; runtime receipts, original failures and hashes are in `chat-cards-310-runtime.json` and the accompanying text logs. Source/task-start hashes and reproduction drivers remain in `.codex-tasks/20261110-chat-cards/`. The preexisting dirty tree is preserved. No commit, push, release, production signing change or APK delivery was performed.

Remaining limits: physical phone/OEM behavior, actual Steam client and browser account interoperability, remote metadata/image availability, sending/receiving against live Steam accounts, and minified on-device card interaction are not verified. Synthetic local callbacks establish UI/send boundaries; they do not prove server-side card conversion or trade completion.
