# 液态玻璃聊天筛选拖动验证（2026-11-13—14）

用户明确选择“拖动玻璃选中块切换筛选”。本轮已接入聊天会话的全部、未读、私聊、群聊、置顶和归档筛选。新增通用选择行，但尚未接入其他页面或富媒体选择器。

## 最终行为

- 从当前选中块按下并横向拖动，玻璃块跟随指针，按实际标签宽度连续改变边界，并随速度和按压形变。其他选项上的拖动仍用于横向滚动；纵向手势交给父级列表。
- 拖动中保留已经确认的筛选和列表，松手吸附完成后才确认一次新筛选。点击选项仍沿原回调切换。
- 靠近可滚动边缘时持续滚动选项，允许拖选屏幕外的归档。位置和滚动补偿使用实际物理坐标，支持 RTL。
- 取消、外部选择变化、选项重排、视口或密度变化及组件卸载会撤销旧手势。减少动画时保留拖选，关闭按压缩放、速度形变和吸附动画。
- 玻璃块在独立布局／绘制层读取边界，指针事件直接更新位置。只有吸附和活动中的边缘滚动创建运动任务；本轮未新增筛选栏性能基准，不据此宣称帧耗时已改善。
- M3E（内部沿用 FIXED 枚举）保留点击选择和选项滚动。筛选容器裁剪移动块，避免它移到容器外。

测试使用独立包 `takagi.ru.monica.steamapp.dockperf`，仅含合成会话和棋盘背景。最终未混淆 Debug 主／测试包联合构建与相关 JVM 检查成功，63.040 秒；62 项 JVM 检查全部通过，无失败、错误或跳过。原底栏优化的验证结果见另一个 dock-performance 报告，本轮没有重新测量其性能收益。

## 前序失败与修正

- 旧主包加最初的一方法测试按预期失败：拖动后仍为 ALL，而期望 UNREAD，runner 7.265 秒。新实现同一原始测试通过，7.871 秒；这证明旧路径缺少拖选，不是应用崩溃复现。
- expanded03 的主包生成后，扩展测试因错误导入和不存在的 M3E 枚举编译失败，48.602 秒。修正为实际成员 API 和 FIXED 风格后，expanded04 联合构建成功，91.201 秒。
- expanded04 两台设备各 8/12。默认视口能容纳全部选项，滚动断言缺少溢出的前提；外部更新、卸载和徽标重排在测试时钟尚未呈现变化时就发出了松手事件。改为 320dp 窄视口，并在松手前断言新选中语义、组件确已移除或 99 徽标已显示，保留原结果断言。
- expanded05 构建成功，172.334 秒；API35 为 11/12，唯一边缘测试仍停在 PINNED。测试停住指针时仅睡眠，没有推进负责边缘滚动的 Compose 帧时钟。最终逐个移动事件推进帧，边缘停留继续推进 1200ms，并在松手前断言归档已实际进入视口。
- final06 同时补充视口／密度作为手势键，以及筛选容器裁剪。两台设备最终完整新交互与既有回归全部通过；此前失败日志保留，未用最终结果覆盖它们。
- API35 的访客外部目录无法从 shell 的存储命名空间读取。最终测试把同样的合成裁图同时写入自有私有目录，经 `run-as` 导出成功；没有提权或读取实际 Monica 应用的数据。
