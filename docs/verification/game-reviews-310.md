# Steam 1.0.310 玩家评测恢复验证

2026-11-20。用户确认问题是游戏详情的玩家评测。保留此前商店／个人统计双页工作，新增修复仍未发布。

## 原因与修改

公开请求旧 `store.steampowered.com/appreviews/{appid}` 返回 302 跳转商店首页。Steam 当前网页脚本使用 `ajaxappreviews/{appid}`；该接口返回原生 JSON 评论。旧服务会吞掉页面失败，仅留下评分统计，因此页面看似无评论且没有重试入口。

评测与评分请求改用当前接口。解析器检查成功标志和评论数组，HTML／失败／缺字段不能当成功空列表。初次页面失败保留可见失败状态与重试；有效空列表单独提示。失败时可继续显示已有缓存，成功空页不恢复旧评论或旧游标；翻页保留去重和账号／游戏／筛选校验。筛选请求失败后保留当前选择并标记第一页失败，重试请求其第一页，不混入旧筛选的评论。新增 3 条文案覆盖英文、中文、日文、俄文、越南文。

## 已取得的证据

- 修前接口路径回归 2 项中 1 项按预期失败；原日志和 XML 保留。
- 修后 13 项评测 JVM 检查通过，另 6 项聊天缓存／发件箱检查通过，联合构建 4m32s。
- MuMu API35/x86_64 的 15 项原生检查通过，runner9.451s，含评测失败重试、成功空状态、真实公开服务两页及页面生命周期／列表回归。
- 公开 620／730 各两页均 HTTP200、success1、每页20条；设备实际生产服务取620两页各20条，ID不重叠。未登录、未发送评论、未使用用户账号。
- 本地 M3E Canvas 的失败／恢复状态实际预览并点击重试；JSON、链接和截图仅保存在忽略目录 docs/design/20261120-review-recovery。

## 最终验证与边界

与聊天任务联合的R8主／测试包构建10m55s、46项JVM检查通过；R8测试运行器在启动前因 androidx.tracing.Trace 被裁剪退出，未计作设备成功。改用独立包、non-debuggable且未压缩的x86_64测试变体，主／测试包构建8m26s，整批35/35通过（25.135s），包含3项评测检查。没有为测试改生产保留规则。

最后的筛选失败重试修改未纳入上述旧编译产物，故补一次2m26s的主／测试包构建及18项评测／ViewModel路由JVM检查，全部通过；检查编译类确认旧状态捕获已移除。更新安装后3项评测检查再次通过（3.938s），包括实际生产服务请求620的两页、失败重试恢复原生正文、成功空结果不显示重试。原生失败／恢复截图已查看，仅在忽略的设计目录。最终筛选失败分支已编译并静态核对，尚无直接调用完整ViewModel的运行时故障注入测试；其最后调整也未重跑R8。

文本及JSON/XML证据在 `game-reviews-310-evidence/`。只移除两份自有测试包，原模拟器、用户、应用与配置保留；清理时发现的两个无关新增包未动。没有提交、推送、发布或APK交付。以上证据不代表所有地区网络、全部游戏或用户真机均已验证。
