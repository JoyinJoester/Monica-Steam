# Monica Steam 切页卡顿修复验证（2026-11-14）

用户要求仅修卡顿，保留液态玻璃及拖动选中块切换筛选。本轮没有升级依赖、版本或架构，没有提交、推送、发布或交付安装包。

## 原因与修改

视频表现为游戏库与聊天快速反复切换。旧宿主每次都重建整页 Compose 树；同包独立关闭页面动画、背景采样或顶部玻璃仍有长帧。原型和正式宿主复用已访问的两页，稳定减少绘制与重建成本。酷安加固样本仅有结构与着色器线索，未将残留类名当作实际帧调度证明。

Library/Chat 共享转场分组，首次访问才创建，暖切换直接更换可见页，底栏继续运动；其他路由沿用原转场。隐藏页不测量、不放置，去除语义并将代理生命周期降至 CREATED。后台同步清空访问集合；失去窗口焦点或打开平台视图只保留当前页。焦点、BackHandler、聊天前台标记与请求消费跟随当前页。

筛选行监听生命周期，ON_STOP 同步撤销松手动画与边缘滚动，重新挂载指针处理以允许返回后继续拖动。聊天线程状态在提交时重新发布，避免返回缓存聊天页后底栏状态失配。闲置刷新指示器不构造 Morph 序列，图片 URL 验证与准备移到 IO；后两项单独不能稳定消除切页长帧。

## 最终同包对照

公共 Monica_Issue136_API_32，emulator-5558，API32/x86_64，合成 SteamLibraryScreen / SteamChatRootContent 真实页面组件与实际底栏，不包含 SteamChatScreen 外层状态准备和主Activity完整账号流程；独立 janktest 包，无 INTERNET。主包与测试包 speed 编译一次，同包依次 baseline → production → production → baseline，每轮预热6次后实触40次，两轮各80次提交。FrameMetrics 与帧提交回调分别记录，未使用 Compose 测试虚拟时钟计性能。

这些数据证明反复切换的重建成本显著下降，仍存在总帧长帧，不能称零卡顿或稳定60 FPS。提交时间是回调到下一次帧提交的代理指标，不是屏幕端到端延迟。两组帧数量不同，动画驱动帧不同；详见原始帧数组与每轮摘要，未把录像28.8 FPS或像素不变当作应用帧率。

## 检查结果与限制

最终 Debug 主/测试包联合构建成功，23 JVM 检查无失败/错误/跳过。设备宿主 6 项、刷新/筛选/底栏/阴影/玻璃回归 30 项通过；包括两种隐藏时拖动取消、回到筛选继续拖动、互斥未读、RTL/大字、当前页返回键、草稿、后台同帧竞态、Dialog、平台视图释放及原生按钮触摸和双向辅助功能排除。

正式包保留真实包名与权限，R8/minify/shrink 打包成功（x86_64 覆盖）。没有安装正式包，R8运行未验证。API32使用玻璃兼容路径；最终截图已查看，折射参数与采样源保留，但最终API33+ AGSL运行未验证。先前报告 SM-A536E 的API35设备实际ABI为x86_64，身份未认证，不能称物理手机；本轮重连被拒绝，未重启它或共享ADB。缓存最多增加一个隐藏页面的内存与状态，首次访问仍须构建；未测完整真实账号、网络、OEM或极端内存压力。

## 失败记录

原隐藏刷新指示器红测试失败；正式宿主前期零尺寸包装仍有旧语义坐标，改为父布局不放置隐藏节点。同帧导航与后台红测试失败，改为STOP清空访问集合。缓存松手红测试确实发生迟到UNREAD提交，持有指针后返回也不能重新拖动，最终均通过。

原生按钮首次失败树显示NATIVE LIBRARY，固定按钮大小写后独立通过；与前置指针测试同批曾出现null active-window root（cached-red13，5/8通过），不将其计为成功，最终宿主独立整批完成双向辅助功能检查。host11也是6/7，旧日志保留。final-b01因预热帧提交迟到，40次点击统计成41次而失败，完全排除该轮；夹具改为每次预热等待实际帧提交，重新构建最终测试包17后完成四轮对照，没有放宽40次断言。所有前序构建、探针、夹具及采样失败留在本地任务raw，关键日志随报告保留；外部ART采样挂住/0字节、simpleperf权限拒绝与设备下线未用作性能结果，未断言采样导致下线。
