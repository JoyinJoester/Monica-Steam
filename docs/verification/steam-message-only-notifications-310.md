# Steam 聊天仅消息通知验证（未发布 1.0.310）

2026-11-19，按用户要求移除“正在以……连接”、等待账号、重连的常驻通知，保留好友聊天消息提醒。

## 实现

删除聊天前台服务及其启动控制器、开机接收器和 specialUse 声明。监听由应用进程内的协程负责，只监听已启用通知且当前选中的账号及存储来源。切换来源、关闭功能会取消旧监听；连接、输入状态与表情反应不发布通知。

保留原消息策略、持久去重、私密锁屏内容、来源和会话绑定的不可变 PendingIntent、单条消息及每应用最多 40 条聊天消息的容量管理。通知失败或取消会释放去重占用。原账号激活、通知地址、路由、去重记录、设置存储和消息判定源码与本任务基线字节一致。

应用启动、通知频道初始化和升级清理取消旧通知 ID 887001，删除两个旧连接频道；不删除或重新启用消息频道。升级接收器仅处理 MY_PACKAGE_REPLACED。语音通话前台服务和 WorkManager 原有声明保留；合并包仍有 WorkManager 的开机权限，不称整包移除开机接收能力。

设置标题改为“聊天消息通知”。英、中、日、俄、越共 30 个可见资源值与实际 APK 逐项核对；旧连接状态资源已移除。README 中英文及发行说明均记录进程限制。

## 验证

- Debug/x86_64 主包、测试包与 35 项相关 JVM 测试联合构建通过，耗时 1 分 27 秒；8 个 JVM 测试类无失败或跳过。后续仅补打测试包，19 秒、19 秒和 18 秒均通过。主 APK SHA256 与首次联合构建保持一致。
- 复用已运行 MuMu API35/x86_64，自有 secondary user14，独立包后缀 `.messagenotifications`。使用合成账号和可注入事件流，不访问用户账号或真实 Steam 网络。
- 最终 11 项完整通知测试通过（17.341 秒），其中 3 项在不清除去重数据的条件下再次通过（5.474 秒）。独立禁用频道测试通过（0.070 秒）。共 12 个不同方法、15 次最终调用通过。
- 覆盖等待账号、连接、重连、网关异常恢复静默；真实 NotificationManager 的好友消息、重放去重、发送消息不提醒、禁用和切来源撤销监听；来源准确取消、私密公开版本、不可变会话路由、40 条容量、其他通知保留、升级旧频道清理及消息频道禁用设置保留。
- 解析实际 APK Manifest，并在安装包信息中检查无聊天前台服务及旧接收器，有升级清理接收器及原语音服务。
- 已查看系统通知栏截图：两条合成好友消息分别显示，无连接常驻消息。截图仅留本地忽略的 docs/design，未作为仓库图片引用。

首轮 11 项通过（17.292 秒）。新增禁用测试晚于首包编译，初次加载报 ClassNotFound，补打测试包后通过。随后在保留 DataStore 的复测中，3 项测试重用固定消息身份，被持久去重正确拦截；改为每次测试生成当前时间身份后最终完整批次及再次运行通过，没有改变生产去重策略。首次通过 adb pull 获取 secondary user 外部目录被拒绝，改用测试私有文件及 run-as 导出。上述失败与中间记录完整保留，未声称所有运行首次全绿。

## 限制与收尾

移除聊天前台保活后，应用进程被系统结束就无法继续实时监听，重新打开后恢复。没有新增云推送、轮询或替代保活机制。仅合成事件、API35/x86_64/Debug；未验证真实 Steam 服务投递、物理设备/OEM、Doze 持续接收或本轮 R8。

保留原 MuMu、用户 0/10/11/12、应用数据与数据盘；清理仅针对本任务 user14 及两个独立测试包。恢复原用户0，不停止此前已运行的 MuMu。没有提交、推送、发布或交付 APK。

初次 adb uninstall 默认针对 Owner，返回 not installed for 0；移除自有 user14 后两个包自动消失，随后全用户卸载返回 DELETE_FAILED_INTERNAL_ERROR。最终 `pm list packages -u`、`pm path` 和 instrumentation 清单核对两个自有包均不存在，用户0/10/11/12保留。清理回执保留全部返回值。

原始构建、JVM XML、设备回执和 30 个编译资源值在同目录 `steam-message-only-notifications-310-evidence/`。任务基线、冻结哈希及详细结果在工作区 `.codex-tasks/20261119-steam-message-only-notifications/`。
