# Direct Dock reuse review

- The latest user video is 409 frames / 13.634 s at about 30 fps. Contact sheet inspected: game-detail tabs and achievement filters show displaced/compressed labels while Dock uses a stable per-item content capture. Previous acceptance only established motion, not equivalence.
- Actual Dock lens code was moved into SteamGlassSelectionLens.kt and BOTH Dock and selectors call it. The depth, dispersion, fixed sampling extent, highlight, surface tint and inner-shadow code is shared. No independent onDrawBackdrop scaling remains.
- Actual Dock transform and drag scale state were moved unchanged and used by both. Selector's former Rect spring, 140 ms press tween and 220 ms tap timer were removed.
- LiquidGlassSelectionMotion is now a geometry/lifecycle adapter around LiquidGlassDockMotionState. Rect interpolation handles unequal width and RTL. Down lifts current selection, click starts travel; release waits until close to destination via the existing Dock engine. Reduced-motion selectors retain their immediate/no-lift behavior.
- Capture uses the existing Dock offscreen/nonzero-alpha helper, a separate selected/tinted row, and scale about each label's own center. Visible labels keep pointer/accessibility semantics; capture clears its subtree semantics.
- Engine cancellation extension revokes generations without touching normal Dock call paths. Layout/style/lifecycle changes dispose the adapter's engine; stale release callbacks cannot commit.
- New tests compare the actual engine every frame (including reversal and drag deformation), plus actual production Dock and selector geometry under the same Compose clock. Older tests that encoded the now-rejected down-travel and artificial same-selected 220 ms pulse are changed to Dock behavior, not described as unchanged regressions.
- build01 failed at the adapter constructor call (trailing callback became the optional frame-wait parameter); corrected explicit callback argument. build02 failed JVM native allocation (G1 mmap 222298112 bytes), preserved hs_err_pid6108.log. Retried with task-local 4 GiB SerialGC / 2 CPUs; did not stop unrelated Java or MuMu.

- build03 passed main/test assembly and 11 JVM checks. Native device01: seven travel/RTL/reduced/cancel methods passed, direct Dock comparison failed before action due to descendant selector, corrected to scoped descendant semantics click. Native images revealed sampling drift despite geometry success; rejected this iteration visually. Miuix source documents layerBlock as the inverse sampling transform; passing it only to outer graphicsLayer omitted compensation. Both Dock and row now pass the same transform into the shared drawBackdrop modifier. build04 failed from an overbroad edit anchor matching the selectedIndex initialization instead of the indicator block; restored the Dock from this task's baseline and reapplied only scoped extraction, preserving preexisting changes. No package from build04 tested.

- build05 passed in 95 s; device02 40/44 passed, including direct 50-frame Dock/selector geometry and reversal comparison. Four failures retained. Actual held/released screenshots found a real stuck-held state: a child click can retire the parent's gesture token before parent up handles it. Explicitly release the engine press in selectFromClick, with a regression that reproduces click-before-parent-release. Two picker optical failures and flat-filter count failure compared number of near-white pixels against preexisting capture; primary tint/filtering makes that count unsuitable. Existing picker width (>1.15), area (>1.20), centering (<4px) and rim thresholds all passed and remain. Filter now additionally measures glyph width/area; both retain minimum readable core checks. No geometry or callback threshold relaxed. Native frames show centered primary-tinted labels.
