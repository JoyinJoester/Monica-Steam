# 聊天菜单高度修复验证

日期：2026-11-09。范围：Monica Steam 未发布 1.0.310 的原生聊天菜单。

## 原因与修改

右上角菜单使用 `TelegramPopupLayout`。玻璃背景是 `MATCH_PARENT` 的普通 View，默认测量会取 `AT_MOST` 提供的最大高度；FrameLayout 又把背景高度纳入自身尺寸，导致三个选项的菜单被撑到屏幕底部。菜单行和弹窗锚点本身没有产生多余高度。

生产修改仅在 `TelegramPopupLayout.onMeasure`：先测量菜单行、边距和内边距，按父级约束确定菜单尺寸，再以确定后的内部尺寸测量玻璃背景。选项、圆角、主题、模糊、入场动画和点击回调沿用原实现。右上角菜单及复用此组件的消息操作菜单同时受益。

## 前后对照

公共 API32 x86_64 模拟器上，旧实现的两个新增回归用例均失败。独立测量中，背景隐藏时为 320px，开启后变为 1440px；实际 `TelegramChatHeaderView.showActionMenu` 弹窗应为 320px，却变为 1806px。旧原生截图展示了与所提供截图相同的长条空白菜单。

修正后的同一组断言及现有原生组件回归共 7 项通过，runner 耗时 16.546 秒。新增检查覆盖液态玻璃和 M3E，1.0、1.5、2.0 字号；两类尺寸约束；玻璃源开启及移除；真实 PopupWindow 的菜单高度、背景边界、文字高度，以及两轮选择第一个选项、关闭和重开。其余 5 项覆盖气泡绘制、Unicode 输入、组合输入、文本布局和附件动画。API33 起的 AGSL 用例由原有 SDK 过滤器排除，未计作通过。

真实弹窗承载在隔离的合成 Activity 中，使用正式菜单与玻璃组件，并未打开真实 Steam 账号会话。手机截图仅用于问题比对，保留在原有私人位置。修复前 1 张、修复后 6 张原生截图保存在本地忽略的 `docs/design` 目录；已查看修复前图、正常字号液态玻璃图及 2.0 字号 M3E 图。文档不嵌入这些图片。

测试包修前构建 71.950 秒、修后 29.942 秒，均成功。应用 Debug 增量打包成功，耗时 101.299 秒；75 项任务中 4 项执行、71 项沿用缓存。对实际 APK 的 DEX 核对确认包含新的内容优先测量方法。隔离测试构建 APK 的 SHA256 为 `93b07128f2aa655faa832d8002c4d0f68c27846cbe2f30fcb559c9cbfcf11e55`；本轮没有安装这个主包。
